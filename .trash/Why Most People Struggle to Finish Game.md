From my experience, and the experience of a lot of Godot devs I meet, the number one reason why people struggle to finish games is because of game development curves.

# What is a development curve?
A development curve ()


The development curve refers to basically the time it takes to add new features to the game on top of the previously made features. When the development curve is highly exponential, it means the time it takes to add new features takes significantly longer than the previous ones, hence why its 'exponential'. So therefore, the time it takes to implement all features when the development curve is exponential will be significantly high. The ideal development curve is a linear one, where the time it takes to add new features stays constant, which makes it very efficient.
![[Pasted image 20261006111609.png|320]]

If you want to avoid getting stuck in development, you need to get as close to a linear development curve as possible, especially for longer term projects. The usual tradeoff with a linear development curves is that there's more initial setup required, making the start of the curve quite steep. Therefore, there's usually some sort of optimal balance between the linearity of the development curve and initial setup. E.g. for a small project like a game jam, it may be more efficient to use less of a linear development curve, to minimise the initial setup. But there are also some ways to minimise the development curve without requiring significant initial setup, which we'll be exploring shortly.

The majority of this workshop is going to be about learning tools to minimise the development curve, so you can more efficiently develop games!
